# SEO: демо, публикация и перенос

## Архитектура

`server/index.mjs` отдаёт HTML из существующих React-компонентов и опубликованного
`/api/site`. `src/entry-server.tsx` изолирует данные запросов через AsyncLocalStorage.
Браузер использует тот же снимок для hydration, без повторной загрузки другого прайса.
Изменения CMS отражаются при следующем запросе; отдельная пересборка контента не нужна.

`src/seo.ts` формирует title/description, canonical, OG/Twitter, JSON-LD, robots и
sitemap. Услуги, врачи, дополнительные страницы и публикации сохраняют существующие
адреса с query-параметрами. Поиск/фильтры не индексируются; UTM не входят в canonical.
Несуществующие материалы возвращают 404; сбой CMS — 503 с Retry-After.

Preview получает черновики только в авторизованном браузере. Публичный SSR никогда
не передаёт cookies посетителя в API, не включает черновики в sitemap и не публикует
служебные учётные данные. Опубликованные фото и документы обслуживаются CMS с её
проверками доступа. Статические копии лицензий/документов не выдаются вместо CMS.

## Безопасное переключение режима

- Демо: `SEO_INDEXABLE=false` (по умолчанию), noindex, запрещающий robots,
  sitemap без публичных адресов. Это намеренно, а не SEO-ошибка.
- Основной сайт: `SEO_INDEXABLE=true` **только после приёмки на реальном HTTPS-домене**.
  Известные демо/локальные адреса конфигурация отвергает. Новый staging-домен тоже
  должен использовать false, даже если его нет в списке защитных проверок.
- В Compose `SITE_URL` SSR-сервера берётся из `PUBLIC_ORIGIN`, CMS доступна по
  внутреннему `http://cms:3001`. Самостоятельный Node-запуск использует SITE_URL,
  CMS_INTERNAL_URL, HOST и PORT (по умолчанию 127.0.0.1:4175).

Сборка для корня домена: `npm run build:production`; запуск: `npm run start:seo`.
Не заменять серверную поставку одним каталогом dist. Нужен Node 24 или Docker,
CMS и постоянное хранилище. На обычном статическом/PHP-хостинге эта схема не работает.
В ручном reverse proxy API/admin/Next направляются в CMS, HTML — в SSR; пример — Caddyfile.

## Проверки разработчика

После `npm run local` и отдельной production-сборки:

```sh
npm run test:seo
node scripts/test-seo-render.mjs
node scripts/test-seo-server.mjs
```

Для браузерной проверки запустить SSR с `SITE_URL=http://localhost:4175/`,
`CMS_INTERNAL_URL=http://localhost:3001`, `SEO_INDEXABLE=false`, затем:

```sh
npm run test:seo:browser
```

Нужен установленный Chromium для `playwright-core`. Тесты используют опубликованный
локальный API; они не изменяют рабочие данные. `test-seo-server.mjs` временно занимает
порт 4176. Он проверяет рабочие флаги индексации на локальном тестовом origin,
а не публикует тестовый домен. Браузерная проверка ожидает сборку с `--base /`.

Подтверждено локально: 12 групп SEO-проверок, 20 изолированных рендеров, 27 URL
рабочей карты сайта, 31 адрес с/без JS, 404/301, поиск и карусель, 45 тестов CMS.
Числа зависят от текущего контента и могут измениться после редактирования.
Сравнены 12 кадров на 390/1440 px: значимых визуальных отличий нет, CSS не менялся.

Использован SEOmator 8.0.1 из seo-skills/seo-audit-skill. Его полный crawl в этой
среде падает с `Maximum call stack size exceeded`; подсчёт слов через `\w` не
учитывает кириллицу. Поэтому балл сканера не заменяет проверку HTTP/HTML/браузером.
Полезные одиночные отчёты запускаются с `--staging` для закрытого демо.

## Перед официальным запуском

1. Подтвердить домен и Node/Docker-хостинг, требования к размещению и данным.
2. Получить URL старого сайта из sitemap и кабинетов поисковиков. Настроить точные
   301 на соответствующие новые страницы, не перенаправлять всё на главную.
3. Проверить медицинские тексты, лицензии, квалификацию, цены и права на материалы
   с клиникой. Не добавлять вымышленные отзывы, рейтинги, авторов или даты свежести.
4. Обновить PUBLIC_ORIGIN, CMS_URL/SITE_URL, сохранённые абсолютные ссылки и CORS.
   Убедиться, что публичные HTML/JSON/метаданные не содержат localhost или demo-URL.
5. Сначала развернуть с noindex. Проверить все три контейнера, публикацию/снятие
   материалов, авторизованный preview, файлы, резервные копии и 503 при отказе CMS.
6. Настроить HTTPS и единственный www/non-www адрес. Включить SEO_INDEXABLE=true
   только на основном сайте; одновременно проверить HTTP-заголовки, meta, robots,
   sitemap и редиректы. Демо оставить закрытым.
7. Проверить JSON-LD в Schema.org/Google Rich Results, зарегистрировать sitemap
   в Яндекс Вебмастере и Search Console с аккаунтов владельца.
8. Измерить LCP/CLS/INP на реальном хостинге, отслеживать 404, индексацию и обращения.

Техническая подготовка не гарантирует позиции и расширенные сниппеты. Для медицинского
сайта важны также достоверность содержания, репутация и корректный перенос старых URL.
