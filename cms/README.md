# Локальная админка клиники

Админка также развёрнута как серверное демо: https://clinic.manath.site/admin.
Локальные и серверные база/пароли независимы. Для подключения, обновления и
переноса на сервер заказчика см. [передачу проекта](../deploy/HANDOFF.ru.md).
Раздел «Перед рабочим размещением» ниже описывает ограничения официального
production-запуска, а не отсутствие работающего демо на VPS.

## Запуск

Нужен Node.js `^22.23.4` или `>=24.22.1` (проверено на 24.22.2).

```sh
npm ci
npm run local
```

Откройте:

- Сайт: http://localhost:4173/medic_corp/
- Админка: http://localhost:3001/admin

Используйте `localhost` для обоих адресов: так авторизация работает и в предпросмотре.

Первый запуск создаёт `cms/.env.local` с отдельным случайным секретом и паролем. Логин — значение `SEED_ADMIN_USERNAME` (по умолчанию `admin`), пароль — `SEED_ADMIN_PASSWORD`. Файл, база, резервные копии и загрузки исключены из Git. Это локальная учётная запись, не пароль для рабочего сайта. Переход со старого входа по email выполняется автоматически с резервной копией базы; пароли и данные сохраняются.

Скрипт проверяет свободные порты, создаёт карту компонентов, подготавливает данные и запускает оба сервера. Повторная подготовка не перезаписывает существующие записи. Ctrl+C останавливает запуск. Данные остаются на диске.

## Как пользоваться

1. Найдите нужный раздел в меню слева (кнопка ☰).
2. Откройте запись или нажмите «Создать новый».
3. Заполните подписанные поля. Адрес записи создаётся автоматически.
4. Черновик сохраняется автоматически. Посетители продолжают видеть опубликованную версию.
5. Для врача, услуги, новости, акции и информационной страницы доступен предпросмотр.
6. «Опубликовать изменения» размещает правки сразу. Обновите вкладку сайта.
7. Во вкладке «Версии» можно сравнить и восстановить предыдущую редакцию.

### Специалисты и услуги

Создайте специалиста, выберите направления, добавьте фото, образование и график. Связь с услугой задаётся в самой услуге во вкладке «Цены и специалисты» — она используется и в профиле врача. Временную недоступность приёма отмечайте полем «Принимает пациентов».

Фото загружается в медиатеку. Для замены выбирайте новое изображение: прежнее сохраняется для истории. В карточках предусмотрено состояние без фотографии.

### Цены

Цены редактируются в разделе «Цены». После публикации сумма используется главной, каталогом, услугой и связанным профилем специалиста. Копейки поддерживаются. Для «от», ОМС и стоимости по запросу предусмотрены отдельные типы.

Сначала создайте и опубликуйте позицию прайса, затем выберите её в услуге. У услуги может быть несколько вариантов цены. Формат Excel/1С ещё не известен: импорт не реализован. PDF загружается отдельно в «Документы» и выбирается в настройках клиники; он не генерируется автоматически из таблицы.

### Новости и акции

Новости публикуются сразу, дата в карточке — дата отображения. Акции имеют начало и окончание по времени Казани / Москвы. Сервер учитывает даты при каждом запросе: будущие акции скрыты, завершённые остаются по старому адресу с соответствующей пометкой и исчезают из действующих предложений. Уже открытая вкладка обновляет данные при перезагрузке.

Текстовый редактор поддерживает заголовки, абзацы, списки, выделение, цитаты и ссылки. В этой версии изображение материала — отдельная обложка; произвольные HTML-вставки, таблицы и изображения внутри текста не предлагаются.

### Документы

PDF и изображения лицензии находятся в «Документы». Файл можно заменить в той же записи. Ссылка `/api/document/{key}` сохраняется. История содержит метаданные и неизменяемые копии файлов; восстановление версии возвращает прежние PDF-байты. Снятые документы закрыты публичному доступу через CMS.

### Общие настройки

- «Контакты и клиника»: телефон, часы, адрес, праздничные изменения, карта, реквизиты, лицензия, полный прайс, временное объявление.
- «Главная страница»: заголовки, главное изображение, подписи и факты о клинике.
- Подборки задаются переключателем «Показывать на главной» внутри соответствующих записей.
- «Страницы и памятки»: ОМС, пациентам и информация о клинике. Новые страницы доступны через `pages/?page={key}`; размещение ссылки задаётся в контенте.
- «Вопросы и ответы»: место показа — главная или каталог услуг.

## Доступ

Редактор управляет контентом и публикует без согласования. Администратор дополнительно создаёт сотрудников. Каждый сотрудник получает собственные логин и пароль, email не нужен. Логином может быть имя, фамилия или другое слово на русском или латинице (2–50 символов, без пробелов). Регистр не важен; одинаковые логины запрещены. Нельзя повысить собственные права или удалить последнего администратора. В версиях сохраняется автор изменения.

Администратор может удалять лишних специалистов, включая несколько сразу. Если специалист выбран в услуге или цене (в том числе в черновике), сообщение назовёт связанные записи: сначала уберите из них специалиста и сохраните изменения. Удаление карточки окончательное; чтобы временно скрыть врача и сохранить историю, снимите его с публикации. Редакторы не могут удалять специалистов. Удаление остальных контентных записей пока закрыто: снимайте их с публикации. Фотографии автоматически не удаляются — они могут использоваться другими карточками и историей.

Самостоятельное восстановление пароля отключено: нет ссылки, страницы восстановления и работающего API сброса. Сотрудники должны сохранить свои доступы. Авторизованный администратор может задать новый пароль в карточке сотрудника — это управление аккаунтом, а не восстановление по письму.

## Хранение и резервирование

- `cms/data/clinic.db` — SQLite, локальная постоянная база.
- `cms/uploads/` — изображения и текущие документы.
- `cms/data/document-history/` — неизменяемые версии файлов документов.
- `cms/.env.local` — секрет и начальные локальные доступы.

```sh
npm run cms:backup
```

Создаёт согласованный SQLite-снимок через `VACUUM INTO`, копирует файлы и проверяет целостность базы. На время копирования не загружайте файлы и не редактируйте документы. Результат находится в `cms/data/backups/` с инструкцией восстановления. Секрет из `.env.local` храните отдельно. Внешняя автоматическая резервная копия для рабочего хостинга пока не подключена.

## Проверки

```sh
npm run test:cms                 # отдельная временная база; права, публикация, версии, файлы
npm run test:cms:browser         # запущенный локальный сайт; Chromium и сквозной сценарий цены
node scripts/verify-cms-create.mjs # создание новости через форму и удаление тестовой записи
npx tsc --noEmit -p cms/tsconfig.json
npm run build                   # статическая демонстрация
npm run cms:build               # сборка серверной CMS
```

Для браузерных проверок нужен установленный Chromium Playwright (`npx playwright-core install chromium`) или `CHROME_PATH`. Скриншоты и отчёт: `test-results/cms/`.

`npm run dev` без `VITE_CMS_URL` сохраняет режим статической демонстрации. `npm run local` включает данные CMS. Если сервер CMS недоступен, сайт показывает ошибку и повторную загрузку, а не незаметно подставляет старые цены из JSON.

## Перед рабочим размещением

Эта поставка предназначена для локальной проверки. Публичная часть пока остаётся Vite-приложением с текущими query-адресами, `noindex` и демонстрационными файлами в `public/`; сервер CMS работает на Next.js. Полная миграция публичных страниц на серверный HTML ещё не выполнена.

После выбора хостинга нужны домен и HTTPS, рабочая база (решить SQLite/PostgreSQL), миграции, файловое хранилище, реальные учётные записи, почта, внешние резервные копии, ограничения reverse proxy, мониторинг и окончательная схема URL/SEO. Удалить из рабочего статического артефакта устаревшие копии документов, оставленные для демонстрационной версии. Не запускать локальный dev-сервер как публичный хостинг.

Начальные материалы перенесены из существующего прототипа для локальной проверки. Они не означают утверждение клиникой цен, квалификации, новостей или медицинских формулировок. Формы заявок, данные пациентов, статьи и интеграция с 1С в этой версии отсутствуют.
